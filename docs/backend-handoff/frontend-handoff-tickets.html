프론트엔드 전달 사항

프론트 수정 요청을 이슈 트래커 스타일의 티켓으로 정리했습니다. MySQL/Gemini 실검증은 아직 미실행 상태이며, AI 브리프 생성은 실제 외부 연동 전까지 성공 생성 활성화가 아닙니다.

Priority · UrgentStatus · To Do

📌 요청 요약

마이페이지/고객 상세 화면에서 customerNo, qrToken 포함 계약으로 변경

🔍 현재 문제점

기존 프론트가 customerNo, qrToken 미포함 응답을 가정하면 QR 관련 UI와 고객 식별 UI가 어긋납니다.

✨ 수정 요구사항

  • /api/v1/customers/me 응답에서 customerNo, qrToken 사용
  • PATCH /api/v1/customers/me 요청 payload에서 membershipGrade 제거
  • QR UI는 customerNo가 아니라 qrToken 기준으로 맞춤

💻 참고 코드 또는 데이터

GET /api/v1/customers/me
PATCH /api/v1/customers/me

📌 요청 요약

조회 응답에 추가된 display 필드를 그대로 화면 렌더링에 사용

🔍 현재 문제점

ID만으로 화면을 그리면 프론트에서 추가 매핑 로직이 필요합니다.

  • Visit 응답의 customerName, storeName 사용
  • VisitRecord 응답의 customerName, caName, storeName, visitedAt 사용
  • Stamp 응답의 customerName, storeName, issuedByCaName, visitedAt 사용

📌 요청 요약

AI Brief latest/history 조회와 생성 흐름을 현재 계약대로 고정

🔍 현재 문제점

latest 조회에 visitId가 빠지거나 생성 성공을 확정 가정하면 연동 오류가 생깁니다.

✨ 수정 요구사항

  • latest 조회는 반드시 visitId query 포함
  • status=FAILED도 정상 조회 결과로 처리
  • MySQL/Gemini 실검증 미실행 상태 문구 반영

💻 참고 코드 또는 데이터
